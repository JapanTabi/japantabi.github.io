# 全站翻譯盤點與實作順序

盤點日期：2026-11-23。目標語言：繁中、簡中、英文、日文、韓文、泰文、越南文、印地文、西班牙文。

## 盤點範圍與方法

- 檢查 `src/` 全部 14 個 HTML 頁面、共用 JavaScript、首頁程式、36 份 JSON、三份文章庫資料與每日更新腳本。
- 以本機 Vite 網站逐頁載入繁中、英文、日文、越南文，共 56 次頁面檢查；比對標題、語言狀態與實際顯示文字。阻擋外部字型、圖片、API，保留本機資源。
- 靜態分析包含尚未打開的攻略、彈窗與文章；動態檢查只涵蓋初始畫面，沒有逐一操作所有篩選、抽屜、表單及第三方訂購頁。
- 14 頁 HTML 共找到 6,784 個含漢字的非 script/style 文字節點，以及 653 個含漢字的 `title`、`alt`、`placeholder`、`aria-label` 屬性值。
- 以上是待分類的原始片段，不是翻譯完成率或最終字串數：含重複頁尾、日文漢字、地名與隱藏內容；也未計入 JavaScript 產生的完整文字。不得直接拿來估算翻譯報價。

## 結論

目前具備九語選擇、偏好保存及跨頁同步，但內容翻譯仍是局部功能。大部分頁面只更新語言狀態，正文不會隨之翻譯。需要同時完成字串抽取、資料翻譯、畫面接線及功能驗收。

## 先處理的接線與資料問題

### 1. 選單九語，但缺譯時直接回退繁中

- `lang_switcher.js` 的文章庫字典僅三語。
- 首頁 `setLanguage()` 使用 `I18N[lang] || I18N['zh-TW']`。
- 富士與專欄也會回退中文；日、韓選項存在但文章字典不存在。
- 應明確區分「該語言已翻譯」「使用指定備援語言」「尚無內容」，不能僅依選單標籤認定內容已切換。

### 2. 現有字典部分根本沒有接到畫面

- 首頁字典有 19 鍵，但首頁 `setLanguage()` 中的一些目標如 `brandSub`、`tripBtnText` 及 `.i18n-btn`，目前首頁沒有對應節點。主要導覽仍是固定文字。
- `renderCommunityFeeds()` 會重新寫入中文季節標題；只在第一次載入替換文字，之後重繪仍會變回中文。
- 特刊翻譯函式引用了十個不存在的 DOM ID：`art1_chf_badge`、`art1_chf_title`、`art1_chf_desc`、`art1_chf_l1`、`art1_chf_l2`、`art1_chf_l3`、`art2_taste_title`、`catalogMainTitle`、`catalogSubDesc`、`footerNote`。其中部分是條件判斷下才呼叫，但對應目標均不在 HTML 中。
- 特刊第 3～8 篇沒有在既有翻譯函式內取得對應文章譯文。
- 應先建立可靠的鍵與元件對應，重繪、開啟彈窗或切換篩選時都從目前語言取字。

### 3. 景點 ID 衝突會造成譯文掛錯

- `spots.json` 的 580 列只有 564 個不同 ID，共 14 組 ID 重複。
- `maruyama_park_sakura` 同時對應「札幌 圓山公園」與「圓山公園祇園枝垂櫻」，不能當作同一景點共用譯文。
- `ashikaga_fuji` 等同地點也有不同文案。先判斷要合併、保留內容版本或重新命名 ID，再按穩定 ID 管理譯文；同步考量既有收藏與連結。
- 兩份列車資料不要直接合併覆寫。可共用相同的可翻譯欄位，保留各頁既有連結及業務欄位。

### 4. 文章庫有卡片，但部分文章頁不存在

六筆卡片中，以下五個目標目前不存在於 `src/` 或 `public/`：

- `articles/zh-tw/niseko-beginner-guide.html`
- `articles/en/niseko-backcountry-apres-ski.html`
- `articles/en/tokyo-disneyland-survival-guide.html`
- `articles/ja/niseko-kiroro-guide.html`
- `articles/ja/tokyo-disneyland-guide.html`

翻譯工作必須包含補建／改接實際文章頁。也要決定這些是同一篇文章的多語版本，還是各語言獨立選題；目前不能僅靠不同語言標題自動建立一對一關係。

### 5. 中文文案與程式判斷混在一起

- 首頁會用中文標籤判斷飯店地區，投稿也會以景點文字比對選項。
- 把原始 `tag`、`title`、選項 `val` 直接覆寫為英文，可能影響搜尋、地點推導、EXIF 配對與篩選。
- 需要將穩定的 ID、城市代碼、類別值與顯示文案分離，原資料保留作相容備援。

### 6. 收藏保存了當時的中文內容

首頁收藏會保存 `title`、`desc`、`tag`、`tips` 等文字。切換語言後若繼續使用快照，收藏抽屜與匯出仍可能是舊語言。畫面應優先以 ID 解析目前語言的內容；保留已不存在項目的舊快照作備援。

### 7. 每日資料會被自動產生

`update_weather.py`、`update_snow.py` 與 `update_rates.py` 會由部署排程執行。不能只手動翻譯生成 JSON，再等下次更新被蓋掉。

- 天氣：城市名稱依 `key` 對應多語；來源天氣文字為日文，建議保留來源描述並提供天氣狀態碼／圖示對應，更新時間標明時區。
- 雪況：分離雪場名稱、統計數字、雪深／新雪單位與顯示句型。
- 匯率：數值與幣別代碼不翻譯，翻譯標題、更新時間、說明與錯誤狀態。

## 所有頁面都要納入的文字層

1. 共用導覽：品牌顯示名稱、入境規範、查機票、租車、排行榜、文章、返回首頁與頁尾。
2. 靜態正文：主副標題、說明段落、FAQ、攻略、行程、交通、注意事項。
3. 資料卡片：名稱、描述、標籤、服務內容、住宿與店家說明、CTA。
4. 互動流程：搜尋、選單、篩選、切換、排序、上傳、分享、複製、收藏、清空、確認、取消、關閉。
5. 狀態訊息：載入中、成功、失敗、逾時、無結果、無文章、表單驗證、相機／檔案／剪貼簿提示；包含 `alert()`、`confirm()` 與 toast。
6. 隱藏內容：所有 modal、drawer、LiveCam、樂園詳細攻略、主題視窗、試算小工具及匯出文字。
7. 輔助文字：`placeholder`、`title`、有意義圖片的 `alt`、`aria-label`、按鈕可讀名稱。裝飾圖片的空 `alt` 不須硬加文案。
8. 網頁及分享資訊：`document.title`、description、OG title／description／locale／image alt；安裝資訊 `manifest.json` 的名稱、描述與語言亦需決定策略。

正式要求多語搜尋收錄及社群分享時，應在建置時提供各語言可讀取的 HTML／metadata，規劃網址、canonical 與 hreflang。單靠瀏覽器載入後換字，不能保證社群抓取器取得指定語言。

## 外部訂購流程也需要一致

首頁及多個頁面各自有 Trip.com、Klook、Booking 的語言映射，通常只列繁中、簡中、英、日、韓、泰；越、印地、西文會回退繁中。部分首頁產生的機票連結還固定帶有 `locale=zh-TW&curr=TWD`，可能與選用的英文站域名不一致。

應統一平台語言映射、優先序與備援策略，逐一驗證平台實際支援的 locale；不能假設三個平台的代碼相同。語言調整必須保留 `Allianceid`、`SID`、`trip_sub*`、`aid` 等既有追蹤參數。此項屬本地化接線，不是翻譯網址字串。

## 內容翻譯前需要確認的語意

- 「免簽 90 天」與「台灣駕照」等內容有特定適用對象，選英文、越文或印地文不代表旅客國籍。翻譯時必須保留條件，不能改成面向所有讀者的無條件承諾；擴充其他國籍資訊應另查官方來源。
- 免稅、優惠券、價格、席位、營運時段、身高／年齡限制屬事實條件，要有來源與更新日期；翻譯不應自行增減條件。
- 「避坑」「續攤」「放電」「神級」「救援」等中文編輯語氣，應轉成目標語言自然且清楚的旅遊用語。
- 「中文教練」「中文司導」「英文菜單」描述服務事實，翻譯成另一語言時仍須忠實說明原本提供的服務語言。
- 日文書法、英文裝飾標語可依品牌設計保留，但操作與安全資訊應以選定語言完整提供。
