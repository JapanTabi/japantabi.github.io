# 本機內容管理後台

## 啟動

在專案根目錄執行：

```bash
npm ci
npm run admin
```

開啟 **http://127.0.0.1:4175/**。保留終端視窗，按 `Ctrl+C` 停止。若要使用其他連接埠，可執行 `ADMIN_PORT=4180 npm run admin`；瀏覽器網址也要改用該連接埠。請使用 `127.0.0.1`，不要改成 `localhost`。

這是依照目前 JSON 資料建立的本機管理後台，僅監聽電腦的 loopback 位址。它不需要 GitHub token 或帳號密碼，也不會被打包到 GitHub Pages。`npm run dev` 是旅遊網站預覽，`npm run admin` 是資料管理，兩者可在不同終端同時執行。

## 編輯與發佈

1. 左側選擇資料類別；手機尺寸可使用上方「選擇資料」下拉選單。
2. 搜尋並選取一筆資料，直接編輯文字、數字、布林值、圖片網址或導購網址。
3. 展開巢狀欄位，可編輯物件、陣列、排序及新增／移除陣列項目。
4. 使用「新增」或「複製」建立項目。陣列中的 `id`、分類物件的鍵值需自行輸入，保持唯一；欄位沿用所選資料，新項目的內容需要補齊。
5. 點「儲存變更」或按 `Ctrl+S`／`Cmd+S`，寫回 `public/data/`。
6. 使用 `npm run dev` 預覽並檢查 Git 差異，執行 `npm run check`，再提交並推送至 `main`。GitHub Actions 部署成功後正式網站才會更新。

「整份 JSON」可批次編輯、新增／刪除欄位或調整特殊結構；格式有誤時禁止儲存。表單會保留原本的欄位及資料型別，不會只寫回畫面上部分欄位。圖片目前編輯網址或既有 `./images/檔名` 路徑；新增圖片請先放入 `public/images/`，後台未提供檔案上傳功能。

## 備份與衝突

每次儲存前會把舊版本備份到 `.admin-backups/<檔名>/`，並以暫存檔取代原檔。這個目錄只保留在本機，不提交 Git，也不會被公開部署。

點「備份與還原」可選取最近 30 份備份還原；還原前也會備份當前版本。更早的備份仍留在磁碟，可自行查閱。時間標示為 UTC。

如果另一個分頁、文字編輯器或 Git 操作更新了同一檔案，舊分頁儲存時會拒絕覆寫。先使用「匯出草稿 JSON」保留自己的修改，再重新載入最新資料並合併。後台不會自動合併衝突，也不會替你 git commit 或 push。

切換資料或關閉頁面前會提示尚未儲存的草稿。「捨棄變更／重新載入」只捨棄草稿，無法取消已儲存內容；已儲存內容可用備份還原。

## 資料注意事項

- 管理目前 `public/data/` 第一層的 29 份 JSON。文章 JS、HTML 內嵌文案與導購設定尚未納入。
- 已有部分重複景點 ID：允許保留並編輯舊資料，禁止增加重複 ID。資料列表以項目位置選取，避免同 ID 指到錯誤項目。
- `trains.json` 和 `trains_database.json` 分別供列車專頁與首頁使用，編輯時需自行決定是否同步。
- 樂園 id 對應 `theme_park_tickets.json`，雪場 id 對應 `resorts.json`。後台有提示，但不會跨檔案自動修改或刪除關聯。
- `snow_today.json` 會在下一次排程被覆寫。
- `locations.json` 是歷史資料，現有網站未讀取。
- 儲存會檢查 JSON、最外層型別、原有清單的 ID／名稱必填條件，以及新增重複 ID；尚未全面驗證每個頁面的資料規則或外部網址有效性。

## 驗證

```bash
npm run test:admin
```

測試會使用暫存資料，驗證儲存、備份還原、衝突、防止跨站寫入與桌面／手機表單操作，不會修改正式 `public/data/`。
